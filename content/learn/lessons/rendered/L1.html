What Amazon owes you, and the reports it hides in

Amazon loses units, damages units, refunds customers who never send the item back, and grades some returns as its own fault. For each of those it owes you money. Since 1 November 2024 it pays most of that automatically, without a case. This playbook is about what the automatic pass misses or underpays, because that is where the money still sits.

On the demo catalogue this course runs on, Tarnhollow (demo data, 24 products, about $3.5M a year), the method finds 123 claims. 72 of them are open today, worth $4,593 at landed cost, or $3,573 once you apply honest approval odds. 37 of them close within 14 days. $825 has already been lost to windows that shut. Every one of those numbers came out of the same reports you can export tonight.

The reports

Everything lives in the seller's own exports. Nothing here needs a tool or an account you don't already have.

Report Where What it reveals
Inventory Ledger Reports → Fulfillment → Inventory Ledger units Amazon adjusted away, with a reason code and, sometimes, its own admission of the shortfall
FBA Customer Returns Reports → Fulfillment → Returns each return with the grade Amazon gave it
Reimbursements Reports → Fulfillment → Reimbursements what Amazon already paid, in cash or in replacement stock, and what it clawed back
Transactions Payments → Transaction View → download every refund, with the order it belongs to

The template

Download the spreadsheet under the video. It has a sheet for each report, helper columns that classify every row, a Claims sheet that dates and values each claim, and a filing log. Every window and approval assumption in it is the same constant Hubricon's own engine runs, so the template and the engine can never disagree. The rows already in it are demo data from the demo catalogue; delete them before you paste your own.

How a claim gets its number

Value is units multiplied by landed cost: unit cost plus inbound freight plus packaging. Amazon reimburses at manufacturing cost, so that is the honest figure. Without a cost sheet the template falls back to 50% of the selling price and says so. Expected value is that value multiplied by an approval probability that is stated, not hidden: 85% for warehouse losses, 70% for refunds without a return, 60% for returns Amazon damaged. Sort by expected value and days left, and you have the order to file in.

What this playbook does not cover

Inbound shipment shortages. They need the shipment reconciliation export, which is a different report with a different window. Lost units after a removal order. Fee overcharges. Each is real; none is in this course.
